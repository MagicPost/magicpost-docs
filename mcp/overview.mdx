The MagicPost MCP server lets any [Model Context Protocol](https://modelcontextprotocol.io)
client (Claude, ChatGPT, Gemini, Perplexity, Grok, Mistral, Cursor, Claude
Code, Codex, custom agents) operate your MagicPost account from within a
conversation, without leaving the chat.

## What it does

- **Generates** posts in your own voice — or in an imported creator's writing style
- **Reads** your analytics, lists your draft / scheduled / published posts
- **Writes** new drafts, schedules posts (same-day & exact-slot warnings), cancels, publishes now
- **Attaches media** supplied by the chat to a draft before scheduling or publishing
- **Finds inspiration** in a global catalogue of high-performing posts
- **Detects & manages leads** from your posts' engagement, scored against your ICPs and synced to your CRM
- **Works for the accounts of your organisation** (org admins) — almost every tool can act on a member's account, as if you had switched to it in the app
- **Refreshes** your LinkedIn data and waits for completion

It's a thin, stateless proxy over our [REST API](/api-reference/overview).
Everything you can do with curl, you can do via the MCP — just from an LLM
conversation.

## Architecture

```
   ┌─────────────────────┐
   │   MCP client        │  Claude, ChatGPT, Cursor, ...
   │  (your LLM tool)    │
   └──────────┬──────────┘
              │  HTTPS, sign-in (OAuth) or Bearer mp_*
              ▼
   ┌─────────────────────┐
   │ mcp.magicpost.in    │  Validates the key (cached 60s),
   │  (MCP server)       │  forwards calls to api.magicpost.in
   └──────────┬──────────┘
              │  HTTPS, same PAT
              ▼
   ┌─────────────────────┐
   │ api.magicpost.in    │  Our Flask backend.
   │  /api/v1/*          │  Runs your operation against Supabase,
   └─────────────────────┘  Airtable, LinkedIn OAuth tokens, etc.
```

## Endpoint

```
https://mcp.magicpost.in/mcp
```

Transport: `streamable-http` (current MCP standard, stateless mode,
JSON responses).

The server is listed in the official [MCP Registry](https://registry.modelcontextprotocol.io)
as `io.github.MagicPost/linkedin-mcp-server`. Its registry metadata, connection
examples and prompt examples live in the
[GitHub repository](https://github.com/MagicPost/linkedin-mcp-server).

Authentication: AI assistants sign you in through the browser (OAuth), with
no key to handle. Clients that cannot sign in send a MagicPost API key as
`Authorization: Bearer mp_...`. The sign-in issues the same kind of `mp_` key
behind the scenes, which you can disconnect from
[Settings → API & MCP](https://app.magicpost.in/account?tab=api-keys).

An agency's client connects to a separate, smaller catalogue with the rights
of their client space: see [Client assistant](/mcp/client-assistant).

## Acting for a member of your organisation

If you are an administrator of an Agency or Team organisation, almost every tool also accepts `member_user_id` (the `user_record_id` returned by `list_org_members`). The tool then works on that member's account exactly as if you had switched to it in the app: the member's plan, quotas, credits, LinkedIn connection, writing style and validation mode apply, and likes or comments go through the member's paced queue. An account manager only reaches the accounts assigned to them.

Billing, credit purchases, credit history, CRM connections, API keys and account security are never handled for a member: those tools have no `member_user_id`.

One exception: with `manage_media_asset` action `send_to_client`, `member_user_id` names the client account that receives the copies.

A caller who is not an admin of the organisation gets `403 org_admin_required`; a member outside your organisation or your scope gets `404 member_not_in_org`. Your key's rate limits apply to every account you act for, but the post generation caps (3 per minute, 20 per day, 50 per week) are counted per account.

With the REST API, send the same id in the `X-MagicPost-Member-Id` header. An endpoint that cannot act for a member answers `400 member_scope_not_supported` instead of silently using your own account.

## What your client lists

The tool list is fitted to the account behind the key:

- **An account that manages no member of an organisation** does not see the organisation admin tools (`list_org_members`, `get_org_metrics_summary`, `list_org_member_posts`, `get_org_member_post`, `create_member_post`, `schedule_member_post`, `add_member_idea_to_notebook`, `list_org_leads`, `get_team_activity`, `list_org_groups`, `manage_org_group`), nor the `member_user_id` input of the other tools. This only shortens the list: if one of these tools is called anyway, the API answers `403 org_admin_required`.
- **A member of an organisation whose plan is limited to analytics** only sees the metrics tools: `list_linkedin_post_metrics`, `get_metrics_summary`, `get_metrics_freshness`, `refresh_my_posts`, plus `list_org_members`, `get_org_metrics_summary`, `list_org_member_posts` and `get_org_member_post` for an admin. Any other tool is refused, as the REST API refuses it (`403 org_perimeter_forbidden`).

A change of role is picked up when the client starts a new session.

## What it does NOT do

- **Billing and account security** — plans, credit purchases, API keys,
  password, two-factor authentication and the LinkedIn connection are managed
  in the web app only.

Tools work on your own account by default. Organisation admins can target a
member's account with `member_user_id` (see above) and read team-wide data
with the `list_org_*`, `get_org_*`, `get_team_activity` and group tools.
