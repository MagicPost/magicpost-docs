## generate_post

Generate a new LinkedIn post and persist it as a draft.

For an org admin, member_user_id generates the post on that member's
account, in their voice: their language, writing styles, settings,
knowledge base, templates and credits, as if the admin had switched to
that account in the app.

Inputs
------
- subject: required. What the post should be about. Free text.
- type: optional. High-level intent:
    'actionable'    → tips, methods, operational lessons
    'aspirational'  → success stories, positive messaging
    'introspective' → reflections, takes, vented frustration
    'promotional'   → launches, lead magnets, valuesales
  When omitted, the type is auto-detected from the subject.
- language: optional. Defaults to the user's UI preference.
- tone: optional. Same vocabulary as the UI ('standard', 'friendly', etc).
- hook: optional. A custom opening line. Inserted verbatim.
- guideline: optional. Extra instructions appended to the prompt.
- signature: optional. Custom signature.
- writing_style_urn: optional.
- template_id + template_kind: optional, always together. The `id`
  and `kind` of an entry returned by list_templates. The post then
  follows that template's structure, hook and length (same as
  "Generate from a template" in the MagicPost editor); `subject`
  is still what the post is about. No `type` is needed.
- template_similarity: optional, only with a template.
    'close'     (default) → keeps the template's structure, hook
                            style and length, rewritten freely
    'identical'           → replicates the template's format and
                            structure very precisely

Templates
---------
When the user asks for a post "from a template", "with my template
X" or "in the format of \<template>", call list_templates first (use
`query` with words from the template's name), confirm the choice with
the user if several match, then pass its `id` and `kind` here. Never
paste a template's text into `guideline` instead: the template mode
uses a dedicated prompt. template_not_found (404) → the id/kind pair
is not visible to this account; list again.

Writing style resolution
------------------------
- DEFAULT (writing_style_urn empty): uses the user's configured style:
  if their UI has `profilePostsActive=true` with a profile URN attached,
  that profile's recent posts feed the prompt as few-shot examples.
  If `profilePostsActive=false`, no style is injected.
- "Generate in MY style" → leave writing_style_urn empty.
- "Generate in the style of `<other person>`": multi-step flow:
    1. Call list_my_writing_styles() to check if that person is already
       imported on the user's account.
    2. If not, call `find_writing_style_profile("<name or URL>")` to
       locate a candidate URN with metadata. Profiles with
       `ready_to_use=true` can be attached immediately.
    3. Call add_writing_style_profile(profile_url) to attach the
       profile to the user's account. If the response is
       `status: 'scraping_in_progress'` or `'import_started'`, tell
       the user to wait 1-3 minutes and re-call add_writing_style_profile
       (idempotent: it flips to 'ready' once enough posts are scraped).
    4. Once `status: 'ready'` or `'already_imported'`, call
       `generate_post(..., writing_style_urn=<the returned urn>)`.
       This overrides `profilePostsActive` for THIS call only.

Rate limits
-----------
Capped at 3 generations per minute, 20 per day, and 50 per week.
A 429 response indicates which window was hit (rate_limited_generation):
surface the limit reset hint to the user verbatim.

Errors that need user action
----------------------------
- credits_insufficient (402) → user needs to upgrade.
- writing_style_not_imported (400) → the URN wasn't on the user's
  account; route through the import flow first.
- rate_limited_generation (429) → cap hit; surface counts + hint.

## list_templates

List the post templates this user can generate from: the same
library as the template picker of the MagicPost editor.
With member_user_id, an org admin lists the templates of that member's
account (pass the same member_user_id to generate_post).

Inputs
------
- kind: optional filter.
    'custom' → the user's own templates (and templates a teammate
               shared with the organisation, with `author_name`)
    'org'    → templates their organisation published for them
    'built'  → the MagicPost catalogue (~90 templates)
  Omitted: all three, the user's own first, then the organisation's,
  then the catalogue.
- category: optional, catalogue category ('actionable',
  'inspirational', 'insights', 'promotional').
- query: optional, case-insensitive text matched against the title
  and the preview. Use it when the user names a template.
- language: optional. Language of the catalogue templates (name or
  code). Defaults to the user's content language. Pass the same
  value you will pass to generate_post.
- limit: 1-100, default 30. `total` tells how many matched.

Returns
-------
`{success, count, total, language, templates: [...]}`. Each entry:
`id`, `kind`, `title`, `category`, `family`, `preview` (first ~280
characters of the template, enough to recognise its structure),
`length_chars`, and `author_name` for a teammate's template.

To generate from one: generate_post(subject=..., template_id=\<id>,
template_kind=\<kind>). Show the user a short list (title + preview)
when the choice is not obvious.

|---|---|---|---|
| `kind` | `string \| null` | null | Kind |
| `category` | `string \| null` | null | Category |
| `query` | `string \| null` | null | Query |

## find_writing_style_profile

Search the global LinkedIn profile catalog by name or LinkedIn URL.

Use this AFTER list_my_writing_styles, when the person the user wants
to mimic is not already imported on their account. The returned
results indicate `ready_to_use` (true iff the profile already has
>= 30 valid posts ingested in our DB).

- query: a person's full name (e.g. "Gary Vaynerchuk") OR a LinkedIn
  URL. Both shapes are handled.
- limit: up to 25, default 10.

Returns
-------
`{success, query, count, results: [...]}`

Each result has:
  urn, full_name, headline, profile_url, followers, valid_posts,
  ready_to_use, similarity.

`similarity` is null when the name contains the query. When nobody
does, the search falls back to names spelled closely (a typo such as
"jasminc alic" for "Jasmin Alić") and `similarity` gives how close
(0 to 1): tell the user which person you found before using them.

After picking a candidate, call add_writing_style_profile(profile_url)
to attach it to the user's account. If the candidate's `ready_to_use`
is false, the import will still succeed but the import endpoint will
return `status: 'scraping_in_progress'` until enough posts are
ingested (~2 minutes).

The catalog is the same for every account; member_user_id is accepted
so the whole style flow can run for an org member.

## add_writing_style_profile

Attach a LinkedIn profile to the user's account as a writing-style
candidate, scraping its posts if needed. With member_user_id, an org
admin adds it to that member's writing styles (their plan quota).

Idempotent: re-calling with the same URL is safe. Use this exact
re-call pattern when the response indicates scraping is in progress.

Inputs
------
- profile_url: full LinkedIn URL (https://www.linkedin.com/in/...).

Returns
-------
One of these `status` values (HTTP status varies):
  - 'already_imported' (200): URN was already on the user's account.
    Proceed straight to generate_post.
  - 'ready' (200): profile had >= 30 valid posts. Just attached.
    Proceed straight to generate_post.
  - 'scraping_in_progress' (202): profile is known but understocked.
    A scrape was queued; the URN is already attached. Tell the user
    to wait ~2 minutes and re-call this same tool: it will flip
    to 'ready' once enough posts are scraped.
  - 'import_started' (202): profile was unknown to our DB; an
    initial scrape was queued. Tell the user to wait ~3 minutes
    and re-call this tool.
  - 'quota_exceeded' (402): user's plan limit reached. Surface
    the hint to the user verbatim.
  - 'invalid_url' (400): URL doesn't resolve to a LinkedIn profile.
  - 'import_failed' (4xx): could not fetch the profile. Verify the
    URL is correct and the profile is public.

Each response shape (when present) includes urn, display_name,
profile_url, valid_posts. Use the returned `urn` as
`writing_style_urn` in generate_post once status is `ready` or
`already_imported`.

| Input | Type | Default | Description |
|---|---|---|---|
| `profile_url` | `string` | — | Profile Url |
| `member_user_id` | `string \| null` | null | Org admins only: act on the account of this member of your organisation (`user_record_id` from list_org_members), exactly as if you had switched to that account in the app. Leave empty for your own account. |

## get_post

Fetch the full record for a single MagicPost owned by the user.

Besides the raw media list (`file_post`), the record carries
`media_type` and `thumbnail_url`, with the same meaning as in
`list_my_posts`.

It reads the posts of ONE account: yours by default. A post of an org
teammate returns `error_type='post_not_found'` (404) unless you pass
that teammate's `member_user_id` (org admins only). So if the post id
came from `list_org_member_posts` or relates to another member, pass
that member's `member_user_id`.

`post_id` MUST be the MagicPost UUID (e.g.
"16a63f9a-0e13-43eb-b502-..."). It is NOT the LinkedIn share URN
exposed as `linkedin_share_urn` by `get_metrics_summary`. Passing a
URN returns `error_type='invalid_post_id_format'` (400).

To resolve a `linkedin_share_urn` into a MagicPost UUID:
  1. Call `list_my_posts(status="published")`.
  2. Find the row whose `linked_in_url_post` contains the URN.
  3. Use that row's `id` here.

Posts published outside MagicPost are not in this table and cannot
be fetched with this tool.

Besides the raw `post` record, the response carries:
- `publication`: `{state, scheduled_at, published_at, linkedin_url,
  error}`. `state` is one of draft, scheduled, publishing, retrying,
  published, failed, missed (scheduled time passed by more than 10
  minutes without publication: it will not go out on its own,
  reschedule it). On failed or retrying, `error` gives `message`
  and, when LinkedIn refused the post, `linkedin_status` (e.g. 422)
  and `linkedin_body` (LinkedIn's raw response). Check it right after
  a scheduled time to fix and republish without waiting for the email.
- `scheduled_comments`: the comments armed on the post.

| Input | Type | Default | Description |
|---|---|---|---|
| `post_id` | `string` | — | Post Id |
| `member_user_id` | `string \| null` | null | Org admins only: act on the account of this member of your organisation (`user_record_id` from list_org_members), exactly as if you had switched to that account in the app. Leave empty for your own account. |

## create_or_update_post

Create a new draft post (no post_id) or update an existing one's text.

`content` is required, except on an update that only changes the poll
or the link preview display.

Poll: pass `poll` = `{question, options, duration}` to add or replace
the post's LinkedIn poll: question up to 140 characters, 2 to 4
distinct options of up to 30 characters, duration ONE_DAY,
THREE_DAYS, SEVEN_DAYS (default) or FOURTEEN_DAYS. A poll and media
cannot coexist: on a post with media the call answers
`poll_media_conflict` (remove the media first with remove_post_media,
only if the user wants the poll instead). `remove_poll=True` removes
the poll of an existing post.

Link preview: when the text holds a URL, the first URL's preview card
is fetched like in the app; the response carries `link_preview` (null
when the page is unreadable) or `link_preview_pending: true` (still
loading, get_post shows it later). Media or a poll are published
instead of the card. On an existing post, `show_link_preview=False`
hides the card (the link stays in the text, as plain text) and
`show_link_preview=True` shows it again, like the editor's toggle.

This tool only creates or updates text and poll. To add an image, video, or PDF,
use attach_media_to_post for a chat-provided file, or the
prepare_post_media_upload / complete_post_media_upload flow for a local
file in a code or CLI client. On success returns
`{success: True, post_id, created: bool}`: use `post_id` (NOT `id`)
when chaining into schedule_post or publish_post_now.

@mentions: write `@[Name](urn:li:person:<id>)` (person) or
`@[Name](urn:li:organization:<id>)` (company page), copied unchanged
from the `mention` field of search_mentions or list_recent_mentions.
A plain "@Name" is published as text, without a tag. When the text
holds a mention that will not become a tag, the response carries a
`mentions` report (`untagged_at_names`, `malformed_urns`,
`will_not_tag`): fix the text before scheduling.

To edit a post owned by an organisation member (e.g. a draft made with
`create_member_post`), pass its `post_id` AND that `member_user_id`.
Only org super_admins can do this; to CREATE a member's draft, use
`create_member_post`.

## attach_media_to_post

Attach one image, video, or PDF to a draft, from a chat file or a
public HTTPS link.

Call this after create_or_update_post and before schedule_post or
publish_post_now. The post must be an unscheduled, unpublished draft,
must not contain a poll. The post ID and scheduled comments are
preserved. alt_text is limited to 1000 characters; the separate title
(shown on a PDF document post) to 400 characters.

Pass exactly one source:
- `media_file`: a temporary file reference supplied by the chat host.
  Never invent or reuse its `download_url`: it is consumed during this
  call and copied into permanent MagicPost storage.
- `media_url`: a public https:// link to the file itself (an image
  hosted on the web, a file the user shared by link). Never a page
  that merely displays the image.
If the chat host offers no file to this tool, do not guess a URL or a
file reference. claude.ai passes neither chat attachments nor files you
created in your sandbox to tools. For something you create yourself (a
carousel, a chart, a visual), use attach_html_slides instead. For a file
the user has, call create_media_drop_link and give the user the link.

Several images: call once per image with append=True (up to 9 images,
in call order; LinkedIn shows them as a multi-image post). A video or
a PDF (carousel) must be the only media. Set replace_existing=True
instead to replace ALL existing attachments with this file. To remove
one attachment, use remove_post_media.

For a draft created by `create_member_post`, pass the same
`member_user_id` here, then use `schedule_member_post`. Only an org
super_admin can attach media to a member-owned draft.

## attach_html_slides

Design a visual or a carousel yourself in HTML/CSS: MagicPost renders it
and attaches it to a draft. One slide becomes an image, 2 to 20 slides
become a PDF carousel (LinkedIn document post). This is the way to attach
something you create (carousel, chart, quote card, infographic): no file
transfer, so it works in claude.ai where your sandbox files never reach
tools.

Each slide is one complete HTML document sized exactly 1080x1350 px
(format "portrait") or 1080x1080 px ("square"): set html and body to that
size, overflow hidden. Rendered by Chromium with scripts and network
blocked: no JavaScript, no external images or CSS. Allowed: inline CSS,
inline SVG (charts, icons, shapes), small images as data: URIs, Google
Fonts (fonts.googleapis.com). Keep text large (body 32px or more) and
inside a safe margin.

Each slide is checked for text that overflows, overlaps or is cut. If any
is found, nothing is attached: you get `issues` per slide, fix those
slides and call again with ALL slides (or pass
ignore_layout_warnings=True). `warnings` (near the edge, low contrast)
never block. `title` is shown on a PDF carousel post.

replace_existing=True swaps the draft's current media. append=True adds a

## schedule_post

## get_insights

Read the insights of the MagicPost Statistics page beyond the raw
stats: how the account compares with similar creators, which formats,
post lengths and days work, and who engages with its posts.

Pick one `view` per call:
- `reach_benchmark`: impressions percentiles (p25, p50, p75, p90) per
  follower tier for every creator tracked by MagicPost, for one complete
  month, plus the user's follower count, tier and median impressions that
  month (`user.tier_percentiles` is the user's tier row). `month`
  (YYYY-MM) must be one of `available_months` (the last 6 complete
  months); omitted = the last complete month.
- `peer_benchmark`: where the user's median impressions per post sit

  p50, p75; `peer_count`). Uses `period` or `date_from` + `date_to`.

  the median of peers in the same follower range; `ratio` > 1 means the

  Uses `period` or `date_from` + `date_to`.
- `impressions_trend`: the user's median impressions per month vs the
  p25 to p90 band of creators in the same tier, over `months` complete
  months (1 to 24, default 12). A missing month means no post that month.
- `post_length`: a 0 to 100 score per word-count bucket (`max_words` 50,
  100, ... 400), based on each post's impressions relative to its
  author's usual level, across all tracked creators; plus the user's
  median word count and bucket.
- `best_days`: a 0 to 100 score per weekday across all tracked creators
  (how often a day is a creator's best day for impressions), plus the
  days the user posts most (`user_top_posting_days`, days with at least
  20% of their posts). For the best hours in a country, use
  `get_recommended_posting_times`.
- `audience`: who likes and comments on the user's recent posts:
  countries, cities, job domains, industries, segments, company sizes,
  follower sizes, Premium / Creator / Open to work shares (percentages of
  analysed profiles; verticals and archetypes are multi-label and can sum
  above 100). `analysis.state` says where the analysis is: `never_run`

  `enriching` (results there, profiles still being completed), `ready` or

  `analysis.reread_after_seconds`. `last_data_at` is the freshness of the
  data.

Or pass `date_from` and `date_to` (YYYY-MM-DD) instead of `period`.

`impressions_trend` or `audience`, like the agency report of the app.

Market-wide figures are cached by the app. The first `reach_benchmark` of a
month can take up to 30 seconds; if it times out, wait a minute and call

## search_inspiration_posts

Search the global LinkedIn inspiration catalogue (NOT the user's
own posts) for high-performing examples to draw inspiration from.

Use this when the user asks things like:
  - "Find me top posts about \<topic>"
  - "Show me viral French posts on remote work this month"
  - "What's \<creator> posting that gets traction?"

Filters
-------
- query: free-text. Matches against post text + theme (PostgreSQL FTS).
- creator_name: partial match on poster's display name.
  ⚠️ ILIKE scan: slower than `poster_urn`. Prefer `poster_urn` when
  you already have it (e.g. from a previous result).
- poster_urn: exact LinkedIn URN: indexed, fast.
- languages: e.g. ["French", "English"]. Use the pycountry English
  name (not ISO codes, not native names).
- formats: subset of \{text, image, video, carousel, article\}.
- post_types: subset of \{actionable, aspirational, introspective,
  promotional\}. Case-insensitive on input; backend matches Capitalize.
- days_range: shortcut "posts from the last N days". Ignored when
  `date_from`/`date_to` are set.
- date_from / date_to: ISO date strings (YYYY-MM-DD). Inclusive.
- min_likes / max_likes / min_words / max_words: numeric bounds.
  Default minimums (20 likes, 80 words, 5 comments) are applied by
  the backend to keep the catalogue noise-free even when filters
  are sparse.

Sorting
-------
- 'recent'       → posted_at DESC
- 'top_likes'    → num_likes DESC (default, best for inspiration)
- 'top_comments' → num_comments DESC (proxy for discussion-driving)

Pagination
----------
- page: 1-indexed. Start at 1, increment to walk through results.
- limit: up to 12 per call. Default 10. The response includes
  `has_more` so you know when to stop.

Returns
-------
`{success, page, per_page, total, has_more, count, posts, filters_applied}`

Each post has: id, text (full), theme, type, format, language,
posted_at (ISO), num_likes, num_comments, num_reposts, words,
poster_name, poster_urn, poster_headline, profile_followers_count,

## create_icp

Create an ICP (Ideal Customer Profile): the kind of prospect the
user wants to find. Leads are scored A/B/C against it, and
`detect_leads` targets every active ICP by default.

Get the user's agreement on the title, description AND filters before
calling: each call creates a new ICP (call `list_icps` first to avoid
a duplicate), and the number of ICPs per account is capped. Ask about
the target countries: most ICPs filter on them, and without a country
filter the ICP matches the whole world.

Definition
- title: short segment name, 3 words at most (e.g. "SaaS founders").
- description: 3 to 4 concrete sentences describing ONLY the target:
  role, company type and context, their problem or need, what they
  are looking for. It is used as is to score every lead, so it must
  not talk about the user or their offer.
- example_urls / negative_example_urls: optional LinkedIn profile URLs
  of people who fit / who look close but must NOT be leads.

Filters (all optional, omitted = no filter)
- countries / excluded_countries: English LinkedIn country names
  ("United States", "United Kingdom", "France", "Germany"). A country
  filter is strict: a lead known to live elsewhere is dropped.
- industries / excluded_industries: LinkedIn industry labels
  ("Software Development", "IT Services and IT Consulting",
  "Marketing Services", "Business Consulting and Services").
- employees / excluded_employees: company size buckets.
- cities / excluded_cities: free text city names.
- gender: 'all' (default), 'f' or 'm'.
- profile_flags: profiles must have ALL listed flags.
- followers_min / followers_max: LinkedIn follower bounds.
A value the app does not know is refused with `error_type:
'invalid_filter_values'`, `invalid_values` and the full
`allowed_values`: fix the values from that list, never drop the
filter silently.

Keywords (strong, weak, to exclude) are generated automatically from
the definition; adjust them afterwards with `update_icp`.

Organisation ICP (admin of a Team organisation): for_org=true creates
it at the organisation level, turned on for the creator and for
member_ids (ids from `list_org_members`) or all_members=true. Members
at their ICP cap come back in `skipped`. The response is then
`{icp, activated, skipped}`. An existing ICP goes to the organisation
with `manage_icp` action 'share_to_org'. An organisation ICP is
created from your own account: for_org is refused with member_user_id.

With member_user_id, the ICP is created for that member (their ICP
cap applies).

Returns the created ICP (with its `id`). Its scoring profile and
keywords are prepared in the background for a minute or two; it is
listed by `list_icps` right away. Errors: `icp_limit_reached` (409:
relay the hint, do not retry), `invalid_input` (400, e.g. an invalid
profile URL).

## detect_leads

Detect new leads from the engagement (likes + comments) on one of
the user's LinkedIn posts.

post_urn accepts a numeric activity ID, urn:li:activity:..., or the
share_urn returned by get_post (urn:li:share:... / urn:li:ugcPost:...).
The post must be synced to the connected LinkedIn profile; direct
reposts are excluded. A post_not_found error requires correcting the
reference or connected profile, not retrying the same call.

⚠️ CONSUMES LEAD CREDITS: 1 credit per prospect scored with at
least a Medium ICP fit (level A/B/C; weak D fits are free and
discarded). The exact cost is NOT known upfront: every engager
matching an ICP gets scored (potentially dozens on a popular post),
so never promise a number.

⚠️ OTHER SIDE EFFECTS: a completed detection also:
- pushes the qualified leads to the user's connected external CRMs
  (Pipedrive/HubSpot/Lemlist/Zapier): an external write that is
  hard to undo;
- sends a recap email if the user enabled it.
The confirm-step response tells you which apply (`crm_destinations`,
`email_recap_enabled`): relay them to the user before confirming.

Two-step confirmation flow:
1. First call with confirm=true (default): returns `success: false,
   warning: 'credits_consumption'` with the targeted ICPs, the
   remaining credits, `crm_destinations` (enabled CRM push rules;
   empty list = no CRM push) and `email_recap_enabled`. Show all of
   this to the user and ask them to confirm.
2. After the user confirms, retry with confirm=false to actually
   start the detection (returns `success: true` with a queued
   payload).

- icp_ids: optional list of ICP ids to score against (from
  `list_icps`). Defaults to all the user's active ICPs.
- Detection runs in the background: poll `get_detection_status`
  afterwards. Returns `error_type: 'leads_quota_exhausted'` (402)
  when no credits remain.
- Re-detecting an already-processed post is a NO-OP until its
  engagement has grown: the response comes back with `success:
  false` and `queued: 0` (`already_synced` in results[]). Tell the
  user nothing was launched in that case: do not claim a detection
  started.
- One detection at a time per account: while one runs on another
  post, the call returns `error_type: 'detection_in_progress'` (409).
  Do not retry right away: poll `get_detection_status` until
  `all_terminal` is true, then launch the next post.
- `results[]` can MIX queued and rejected ICPs (e.g. `queued: 2`
  with one `already_synced` entry). Report both to the user: which
  ICPs were launched and which were skipped, and why.
- member_user_id: detect on a post of that member's LinkedIn profile,
  against the member's ICPs. It consumes the MEMBER's Leads credits
  (`credits_account` in the response): tell the user so.

## get_org_metrics_summary

Compact analytics for the org or one specific member.

- When `member_user_id` is omitted: returns one compact summary per
  team member (name, totals, follower growth, top posts). Use this for
  "how is the team doing?" questions.
- When `member_user_id` is set: returns ONE detailed summary for
  that member, same shape as `get_metrics_summary` for the caller's
  own account.

`top_n` defaults to 3 in team view (response stays token-efficient
for an LLM); set higher when drilling into a single member.

`summary.followers.gained` is null when LinkedIn did not provide
enough snapshots to cover the whole period. Check follower `coverage`;
`available_range_gained` only covers the returned dates.
`summary.followers.daily` contains profile-level daily gains.

Each `top_posts` entry carries `media_type` (`image`, `video`,
`document`, `article`, `poll` or `text`) and `thumbnail_url`: the post's
image, the video's preview frame, the document's first page or the
article image, as a URL you can embed in a report. It is null for text
and poll posts, and when no image was stored for the post.

Identifiers (IMPORTANT):
`top_posts[].linkedin_share_urn` is the LinkedIn share URN, NOT the
MagicPost UUID expected by `get_post`, `get_org_member_post`,
`schedule_post`, `cancel_scheduled_post`, `publish_post_now`,
`schedule_member_post`, or `create_or_update_post`. Passing it to
those tools returns `error_type='invalid_post_id_format'`.

To act on a top post, resolve the URN to a MagicPost UUID via
`list_org_member_posts(member_user_id=..., status="published")` and
match the URN against the row's `linked_in_url_post` field. Then read
its full record with `get_org_member_post`. Posts published outside
MagicPost have no MagicPost UUID and cannot be acted on.

## list_org_member_posts

List posts across the org, optionally scoped to one member.

- When `member_user_id` is set: only that member's posts. Useful for
  "show me Alice's drafts" or "what is Bob scheduling next?".
- When omitted: posts grouped by member (each with `limit` posts
  starting at `offset`). Use for "what's the team posting this
  week?".

`status` is the lifecycle filter (`draft` / `scheduled` / `published`),

Each post row carries `media_type` (`image`, `video`, `document` or
`text`) and `thumbnail_url`: the post's first image, the video's
preview frame or the document's cover, as a URL you can embed. It is

ONE post's full record (full text, media, stats…), pass that `id` to
`get_org_member_post(member_user_id=..., post_id=...)`, or to
`get_post` with the same `member_user_id` (without it, `get_post`
only reads your own posts and returns `post_not_found`).

## get_org_member_post

Fetch the full record of ONE post owned by a member of your org.

Org-admin read of a member's post, same record as
`get_post(member_user_id=..., post_id=...)`. Use this when you already have a member's post UUID (typically
from `list_org_member_posts`) and need its full content/metadata
(full text, schedule date, LinkedIn URL, stats, media, etc.). The
record also carries `media_type` and `thumbnail_url`, with the same
meaning as in `list_org_member_posts`.

Only callable by org super_admins. Both arguments are REQUIRED:
  - `member_user_id`: the post owner's user id, exactly as returned by
    `list_org_members` (`user_record_id`) or `list_org_member_posts`.
    It must be a member of YOUR org.
  - `post_id`: the MagicPost UUID of the post (e.g.
    "df1cbd56-a7c0-41f4-b929-5d242bed12eb"), as returned in the `id`
    field by `list_org_member_posts`. This is NOT the
    `linkedin_share_urn` from `get_org_metrics_summary`: passing a URN
    returns `error_type='invalid_post_id_format'` (400).

Typical chain:
  1. `list_org_member_posts(member_user_id=..., status=...)` → read the
     target row's `id`.
  2. `get_org_member_post(member_user_id=..., post_id=<that id>)`.

Error shapes:
  - `error_type='org_admin_required'` (403): you are not an org admin.
  - `error_type='member_not_in_org'` (404): `member_user_id` is not in
    your org.
  - `error_type='post_not_found'` (404): the post does not exist, is
    deleted, or does NOT belong to `member_user_id` (IDOR guard: you
    cannot read another member's post by passing the wrong owner).

`get_post` without `member_user_id` only reads your own posts and
returns `post_not_found` for a teammate's post.

| Input | Type | Default | Description |
|---|---|---|---|
| `member_user_id` | `string` | — | Member User Id |
| `post_id` | `string` | — | Post Id |

## schedule_member_post

Schedule a post on behalf of an org member.

Only callable by org super_admins. The post must belong to
`member_user_id` (you can't move someone else's post by accident).

Defaults:
  - `timezone` falls back to the member's stored userTimezone (NOT
    yours). Set it explicitly if you want to schedule in your own
    timezone instead.
  - `at_iso` is interpreted in that timezone unless the string
    already has an offset.

Same warning flow as `schedule_post` (same_day_posts /
exact_slot_conflict): computed against the MEMBER's existing
scheduled posts. Show the warning to the user, then retry with
`confirm_*=false` to force through.

If the member's LinkedIn token has expired, the response has
`actionable: true` with a `hint` telling you to ASK THE MEMBER to
reconnect: only they can, not you. Surface that hint verbatim.

| Input | Type | Default | Description |
|---|---|---|---|

| `post_id` | `string` | — | Post Id |
| `at_iso` | `string` | — | At Iso |
| `timezone` | `string \| null` | null | Timezone |
| `confirm_same_day` | `boolean` | `true` | Confirm Same Day |
